### **Pattern 46: Multi-Agent Coordination \& Conflict Prevention Protocol**

**Problem:** Multiple Comet agents working in parallel on the same project (GitHub, Replit, etc.) can:

- Run duplicate tests (wasted compute)
- Create merge conflicts
- Block each other's work (e.g., one agent holds a build lock)
- Overwrite each other's changes
- Miss dependencies between tasks

**Solution: Distributed Agent Coordination System**

#### **1. Central Task Registry (Redis/LanceDB)**

Create a shared state store that all agents check before starting work:

```typescript
// server/services/agentCoordinator.ts
interface AgentTask {
  taskId: string;
  agentId: string;
  taskType: 'build' | 'test' | 'deploy' | 'ui-audit' | 'code-fix';
  resource: string; // file path, test suite, etc.
  status: 'claimed' | 'in-progress' | 'completed' | 'blocked';
  dependencies: string[]; // taskIds this depends on
  blockedBy: string[]; // taskIds blocking this
  startedAt: timestamp;
  expiresAt: timestamp; // Auto-release if agent dies
}

class AgentCoordinator {
  // Before starting work, agent claims task
  async claimTask(agentId: string, taskType: string, resource: string): Promise<boolean> {
    // Check if resource is already claimed
    const existingClaim = await redis.get(`task:${resource}`);
    if (existingClaim) {
      const task = JSON.parse(existingClaim);
      if (task.expiresAt > Date.now()) {
        return false; // Resource busy
      }
    }
    
    // Claim with expiration (5 min default)
    const task: AgentTask = {
      taskId: uuid(),
      agentId,
      taskType,
      resource,
      status: 'claimed',
      dependencies: [],
      blockedBy: [],
      startedAt: Date.now(),
      expiresAt: Date.now() + 300000 // 5 min
    };
    
    await redis.setex(`task:${resource}`, 300, JSON.stringify(task));
    return true;
  }
  
  // Heartbeat to keep claim alive
  async renewClaim(taskId: string): Promise<void> {
    const key = `task:${taskId}`;
    await redis.expire(key, 300); // Extend 5 more minutes
  }
  
  // Release when done
  async releaseTask(taskId: string): Promise<void> {
    await redis.del(`task:${taskId}`);
  }
  
  // Check dependencies before starting
  async checkDependencies(taskId: string): Promise<boolean> {
    const task = await this.getTask(taskId);
    for (const depId of task.dependencies) {
      const dep = await this.getTask(depId);
      if (dep.status !== 'completed') {
        return false; // Dependency not ready
      }
    }
    return true;
  }
}
```


#### **2. Task Type Conflict Matrix**

Define which task types can run simultaneously:

```typescript
const CONFLICT_MATRIX = {
  'build': ['build', 'deploy'],           // Can't build while deploying
  'test': [],                              // Tests can run in parallel
  'ui-audit': ['ui-audit'],                // One UI audit at a time
  'code-fix': [],                          // Multiple fixes OK
  'deploy': ['build', 'deploy', 'test'],  // No other ops during deploy
  'db-migration': ['db-migration', 'build', 'deploy'] // Critical lock
};

async canStartTask(taskType: string): Promise<boolean> {
  const conflicts = CONFLICT_MATRIX[taskType] || [];
  const activeTasks = await redis.keys('task:*');
  
  for (const key of activeTasks) {
    const task = JSON.parse(await redis.get(key));
    if (conflicts.includes(task.taskType)) {
      return false; // Conflicting task in progress
    }
  }
  return true;
}
```


#### **3. Hierarchical Agent Roles**

```typescript
enum AgentRole {
  ORCHESTRATOR = 'orchestrator',  // Mr. Blue - assigns work
  BUILDER = 'builder',             // Code changes
  TESTER = 'tester',               // E2E/unit tests
  AUDITOR = 'auditor',             // UI/accessibility audits
  DEPLOYER = 'deployer'            // Build & deploy
}

// Orchestrator assigns non-overlapping work
class MrBlueOrchestrator {
  async assignTasks(agents: Agent[]): Promise<void> {
    const pendingWork = await this.getPendingWork();
    
    // Partition work by resource and priority
    const taskGroups = this.partitionTasks(pendingWork);
    
    for (const agent of agents) {
      const compatibleTask = taskGroups.find(group => 
        agent.role === group.requiredRole &&
        !group.assignedTo
      );
      
      if (compatibleTask) {
        await this.assignTask(agent.id, compatibleTask);
      }
    }
  }
  
  private partitionTasks(tasks: Task[]): TaskGroup[] {
    // Group by file/resource to prevent conflicts
    // Example: All fixes in client/src/pages/onboarding.tsx → one agent
    return tasks.reduce((groups, task) => {
      const resource = this.getResourcePath(task);
      let group = groups.find(g => g.resource === resource);
      if (!group) {
        group = { resource, tasks: [], assignedTo: null };
        groups.push(group);
      }
      group.tasks.push(task);
      return groups;
    }, []);
  }
}
```

```typescript
class AgentEventBus {
```

**What it does:** Makes agents execute tasks **10x faster** by running independent operations in parallel instead of sequentially.

```typescript

  await storeInDatabase(error);      // Wait 1s
  await indexInLanceDB(error);       // Wait 1s
}
// Takes 20 seconds for 10 errors
```

**The Solution:**

```typescript
// FAST: Parallel execution (2s total)
await Promise.all(
  errors.map(async (error) => {
    await storeInDatabase(error);    // All 10 run simultaneously
    await indexInLanceDB(error);     // All 10 run simultaneously
  })
);
// Takes 2 seconds for 10 errors - 10x faster!
```

**Key Rule:** Only parallelize when operations are **independent** - don't parallelize if operation B needs the result from operation A.
