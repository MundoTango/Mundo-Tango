## CONTINUOUS LEARNING SYSTEM

### Learning Sources

```typescript
interface LearningSource {
  type: 'work_completed' | 'research_found' | 'god_command' | 'error_learned' | 'user_feedback';
  content: string;
  timestamp: Date;
  agent: string;
  priority: 'critical' | 'high' | 'medium' | 'low';
}
```

### Learning Loop

```
┌─────────────────────────────────────────────────────────────┐
│                   CONTINUOUS LEARNING LOOP                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. CAPTURE                                                 │
│     └─ Every task → Extract lessons learned                │
│     └─ Every error → Document root cause + fix             │
│     └─ Every research → Summarize key insights             │
│     └─ Every god command → Store as directive              │
│                                                             │
│  2. PROCESS                                                 │
│     └─ Categorize by agent domain                          │
│     └─ Identify patterns across learnings                  │
│     └─ Link to existing knowledge                          │
│     └─ Prioritize by impact                                │
│                                                             │
│  3. STORE                                                   │
│     └─ Update agent memory files                           │
│     └─ Add to MB.MD patterns if significant               │
│     └─ Update replit.md if architectural                   │
│     └─ Store in LanceDB for semantic search               │
│                                                             │
│  4. APPLY                                                   │
│     └─ Load relevant learnings before each task            │
│     └─ Adjust behavior based on past mistakes              │
│     └─ Apply god-level directives with highest priority   │
│     └─ Share learnings across agent hierarchy             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### God-Level User Commands

God-level users (admin, CTO role) can issue commands that become permanent directives:

```typescript
interface GodCommand {
  command: string;
  issuedBy: string;
  timestamp: Date;
  scope: 'global' | 'agent-specific' | 'temporary';
  targetAgents: string[];
  priority: 'override' | 'high' | 'normal';
  expiresAt?: Date;
}
```

**Examples:**
- "All agents must test before completing" → Stored globally
- "CTO Agent: Prioritize performance over new features" → Agent-specific
- "Until launch: Focus only on critical bugs" → Temporary with expiry

## CROSS-AGENT COMMUNICATION

Leadership agents communicate via A2A protocol:

```typescript
interface LeadershipMessage {
  from: LeadershipAgent;
  to: LeadershipAgent;
  type: 'request' | 'directive' | 'report' | 'escalation';
  content: string;
  priority: 'urgent' | 'high' | 'normal' | 'low';
  requiresResponse: boolean;
}
```

IC Agent → Head Agent → VP Agent → C-Suite → CEO → God-Level User (Scott)
